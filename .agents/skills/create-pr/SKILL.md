# Create PR

## 실행 주체

PR 생성은 반드시 서브 에이전트에 위임한다. 부모 에이전트는 요청과 기존 승인 범위를 정리해 전달하고, 결과를 확인해 사용자에게 보고한다. 이 스킬을 읽고 위임받은 서브 에이전트는 직접 수행하며 다시 위임하지 않는다. 위임 도구를 사용할 수 없으면 제약과 준비한 내용을 보고하고 PR 생성은 중단한다.

서브 에이전트에게 저장소 절대 경로, 이 스킬의 절대 경로, 사용자 요청, 기존 승인 범위, 알려진 검증 결과를 전달한다. 대상 저장소·base/head 브랜치·언어·draft 여부가 이미 지정되었다면 함께 전달한다. 모르는 값은 추측해서 확정하지 말고 서브 에이전트가 저장소에서 확인하게 한다. 같은 브랜치를 여러 에이전트가 동시에 수정하거나 중복 PR을 생성하지 않게 한다.

## 언어와 템플릿 선택

서브 에이전트가 다음 기준으로 제목과 본문의 언어를 정하고, 선택한 참조 파일만 읽는다.

1. 사용자가 지정한 언어를 우선한다. 저장소의 필수 기여 형식과 충돌하면 충돌을 설명하고 확인한다.
2. `AGENTS.md`, `CONTRIBUTING` 및 저장소 PR 템플릿의 명시적인 언어 규칙을 따른다.
3. 명시적인 규칙이 없으면 README, 기여 문서, 최근 PR에서 실제 사용하는 언어를 근거로 판단한다. 해외·국제 오픈소스 프로젝트는 영문, 한국어 중심 프로젝트는 한국어를 사용한다. 사용자와의 대화 언어나 소유자 이름만으로 판단하지 않는다.
4. 근거가 부족하거나 서로 충돌해 선택하기 어렵다면 사용자에게 언어만 확인한다.

- 영문: [references/pr-template.en.md](references/pr-template.en.md)
- 한국어: [references/pr-template.ko.md](references/pr-template.ko.md)

저장소 고유 PR 템플릿에 필수 항목이 있으면 그 구조와 항목을 보존하고, 선택한 참조의 작성 기준을 적용한다. 템플릿 파일 자체를 저장소의 `.github`에 설치하거나 덮어쓰지 않는다.

## 서브 에이전트 작업

1. 적용되는 저장소 지침과 Git 상태를 읽는다. 원격 저장소, 작업 브랜치, 실제 대상 base, base와 head 사이의 커밋·diff, 미커밋 변경을 확인한다. fork에서는 대상 저장소와 head 소유자를 구분한다. 기존 PR이 있는지도 확인한다.
2. PR에 포함할 변경을 확인한다. 관련 검증을 수행하거나 이미 확인된 결과를 사용하되, 실제 실행 여부·결과·검증 한계를 정확히 기록한다. 미커밋 변경은 PR에 포함된 것처럼 설명하지 않는다.
3. 선택한 언어와 템플릿으로 실제 최종 diff에 맞는 제목·본문을 완성한다. 문제와 변경 후 동작을 먼저 설명하고, 구현 상세는 검토에 필요한 만큼만 포함한다. 관련 이슈는 확인된 경우에만 연결한다. UI 변경에 시각 자료가 있으면 추가한다.
4. 기존 세션의 권한과 저장소 규칙을 준수한다. PR 생성 요청은 원격 PR 생성의 승인으로 취급하며 이미 승인된 작업을 재확인하지 않는다. 필요한 커밋은 저장소 커밋 규칙을 따른다. push가 필요하면 기존 승인 범위를 확인하고, 승인되지 않은 push는 대상 원격·브랜치와 준비된 제목·본문을 제시한 뒤 승인을 받는다. force push, 기록 재작성, merge는 이 스킬의 범위에 포함하지 않는다.
5. 사용 가능한 GitHub 커넥터를 우선 사용하고, 필요한 기능이 없으면 인증된 `gh` CLI를 사용한다. 저장소·base·head를 명시해 생성한다. CLI의 여러 줄 본문은 UTF-8 임시 파일과 `--body-file`로 전달한다. draft 여부는 사용자 요청과 저장소 규칙을 따르고, 결정 근거가 없으면 준비 완료 상태는 일반 PR, 미완료 상태는 draft로 생성한다.
6. 생성 결과에서 URL·대상 저장소·base/head·draft 상태·제목과 본문을 확인한다. 타임아웃 등으로 성공 여부가 불확실하면 해당 head의 PR을 조회한 뒤 재시도 여부를 결정한다. 기존 PR이 있으면 중복 생성하거나 요청 없이 수정하지 않고 URL을 반환한다. 인증·권한 오류는 우회하지 말고 준비된 내용과 필요한 조치를 보고한다.

## 결과 보고

서브 에이전트는 PR URL, 제목, 선택한 언어와 근거, base/head, draft 여부, 검증 결과와 남은 제약을 반환한다. 부모 에이전트는 실제 생성 여부를 확인하고 사용자에게 PR 링크와 핵심 검증 결과를 간결하게 보고한다. 승인이 필요한 작업이 남았다면 완료로 표시하지 않고 준비된 결과와 필요한 승인만 전달한다.
